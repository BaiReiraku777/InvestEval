## 核验和评分口径

- **事实。** 按声明的证据引用定位实体与字段，再按数据日期和报告期取对应证据。同一快照的原始来源冲突、缺证或来源未收录时进入待核验。对于旧快照，须有该快照自己的证据才能评判数值。明确要求注明来源时，未引用来源单独归因为遗漏。数值先匹配单位量纲并换算，再按证据单位的半个末位精度比较。旧样例的声明可省略 `unit` 和数据日期，沿用所引用证据的单位和声明日期记录。
- **时效。** 以回答时间为基准，时间戳须带时区。样例策略采用盘中 30 分钟、收盘 96 小时、基金净值 168 小时、产品资料 365 天。行情与净值的年龄以观测时间计算，产品资料优先取更新时间。历史证据核对指定时期，显式有效期和热点有效期均包含截止时刻。最新数据已有更新快照时，旧快照触发过期。无法确定策略、时点或时间顺序时进入待核验。这些时限用于模拟数据，业务接入可按来源配置策略和有效期。
- **画像。** 优先使用预置对照，为其余案例从同问题、同模型、同 Prompt、同数据集且原始证据相同的回答中查找不同画像。比较客观声明的值、单位和时期。对照结论记录到配对双方并提供对照回答 ID。表述和解释深度可独立变化，缺少可比较声明时进入待核验。
- **合规与隐私。** 检测保证收益、直接买卖指令、必需的风险披露和明确的个人标识格式。风险披露适用于显式要求披露的案例、有买卖指令或收益承诺的回答。测试覆盖否定、风险教育、已脱敏手机号和理由脱敏。规则使用文本模式，语义语境的覆盖有限。
- **计分。** 各维得分为 `100 × 通过数 ÷（通过数 + 失败数 + 待核验数）`。没有适用项的维度在 `scoreBreakdown` 中以 `null` 表示，汇总时按剩余维度的原权重归一化。兼容预置结果的顶层维度字段用 0 表示不适用，取展示或聚合值时使用 `scoreBreakdown`。相关性、事实、时效、个性化、合规与隐私权重依次为 20%、25%、15%、15%、25%，总分保留一位小数。
- **状态。** 严重合规或隐私命中始终为高风险失败。其余未完成的评测为警告。规则已执行完毕时，总分低于 60 为失败，存在归因或低于 80 为警告，其余通过。待核验理由保存在 `checks`，确认失败的检查同时进入 `findings` 并附归因代码和修复方向。

## 生产服务冒烟验证

构建后运行 `npm run start`，使用 `POST /api/evaluate` 和 JSON 请求体 `{"answerId":"IE-020"}`。响应中 `result.source` 为 `run`，`executionStatus` 为 `complete`，`totalScore` 为 100。按表中 ID 发送请求可复现六类归因。

## LLM Judge 接口与页面

`POST /api/evaluate` 接受 `{"answerId":"IE-020"}` 或 `{"answerIds":["IE-020","IE-024"]}`。批量最多 5 条，同一批重复 ID 只调用一次。超限、无效输入及未知 ID 在调用模型前拒绝。有效请求返回 `results`，每项分别带 `ruleResult`、`judgeResult`、`executionStatus`、`mode` 和 `highRisk`。单条请求保留 `result` 作为规则结果的兼容字段。不完整的批次仍返回规则等已获得的结果；调用端以 `executionStatus` 判定是否完整。缺少 API Key 时 `mode` 为 `rules_only`、`judgeResult.status` 为 `not_configured`。

模型以 JSON 模式返回评测对象。服务端校验 JSON、必填字段、风险枚举和 0–100 的数字分数。事实错误归因须有规则已确认的数值或单位不符。无证据、来源缺失或证据冲突须查看规则中的待核验与缺少来源标记。Judge 不提供金融事实准确分。模型服务错误、30 秒超时及不合法输出均令本次评测不完整，单条失败不丢弃批次中的其他有效结果。

生产构建后运行 `npm run test:judge`。它启动真实 Next.js 路由和本地模拟上游，覆盖规则模式、批量与去重、成功 JSON、错误响应与正常结果同批、Markdown 包裹、越界分、无依据事实归因、账户标识脱敏及响应体超时。模拟上游用于验证协议和失败路径。配置真实模型后，在问答评测中心勾选 `IE-020` 和 `IE-024` 运行，对照按钮下方的 Judge 结果与案例详情保存的记录；其中 `IE-024` 的高风险规则结果始终保留。
