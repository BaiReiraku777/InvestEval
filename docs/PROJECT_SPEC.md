# InvestEval 项目规范

依据根目录 [README.md](../README.md) 的题目与提交要求，以及 [AGENTS.md](../AGENTS.md) 的 MVP 设计。本规范用于后续开发与验收。MVP以及提交期限为24小时。

## 1. 产品定位与主流程

InvestEval 面向投资产品团队，评测投资 Agent 已生成的回答。团队可以查看质量分数和具体问题，追溯核验证据，复核争议结果，比较模型、Prompt 与数据集版本，并检查不同用户画像下的客观事实是否一致。

1. 从预置数据集读取问题、回答、版本、匿名画像、证据和热点上下文。
2. 在问答评测中心启动自动评测。规则引擎核验数字、单位、来源、日期与时效，并检测合规和隐私信号。LLM Judge 按意图评估回答语义。
3. 汇总五个维度的得分，判定评测结果，生成可追溯的 Bad Case 归因。严重合规违规或隐私泄露触发高风险判定。
4. 从列表进入详情，核对回答、原始证据和画像对照，确认或驳回自动发现并记录备注。另行记录对回答的有帮助或无帮助反馈。
5. 在总览查看当前质量和风险分布，在版本对比中查看同一批 Case 的配对结果。

## 2. 范围与优先级

| 优先级 | 功能 |

## 3. 技术架构

| 层或模块 | 技术与职责 |
| --- | --- |
| Web | Next.js 16 App Router、React 19、TypeScript 7、Tailwind CSS 4，运行在 Node.js 26 LTS 上。四个业务页面，图表使用简单 CSS。 |
| 评测接口 | Next.js Route Handler `POST /api/evaluate`。基于预置 Case 和回答版本读取评测输入，执行规则检测和 Judge 调用，返回评分、证据引用、归因及执行状态。 |
| Rule Engine | 按实体、指标、日期和单位核验声明，检查来源、证据／热点有效期和合规隐私规则，比较画像对照中的客观事实。 |
| LLM Judge | 由服务端调用 Kimi K3 或其他 OpenAI-compatible 模型。按意图评估相关性、完整性、表达及语义风险，返回可校验的结构化结果。金融事实结论以原始证据核验为准。 |
| 评分与归因 | 合并规则与 Judge 输出，计算各维与综合分，生成问题明细和风险判定。严重规则命中优先于综合分和 Judge 的正向结论。 |
| 数据和状态 | JSON 存放样例、基准结果和版本。`localStorage` 保存当前浏览器的评测结果、复核和反馈。刷新后可恢复，同源不同浏览器各自保存。 |
| 部署和版本管理 | Vercel 部署，GitHub 托管源代码。Judge 的密钥和提供方配置仅在服务端环境变量中读取。 |

`app/` 放页面和评测接口，`components/` 放共用 UI，`lib/` 放评测、评分、归因、状态和类型，`data/` 放种子 JSON，`docs/` 放规范、测试说明和 AI 使用记录。具体拆分随实现规模调整。

## 4. 核心数据结构

以下是逻辑实体与关键字段，字段名可随 TypeScript 实现调整。

| 实体 | 关键字段与关系 |
| --- | --- |
| `Case` | 稳定 `caseId`、意图、问题文本、判分要点、预期核验字段、证据引用、热点引用。是否询问「最新」由案例的意图和题目约束明确。 |
| `AgentAnswer` | `answerId`、`caseId`、回答正文、回答时间、来源标注、模型与 Prompt 版本、数据集版本、可选画像 ID。按回答实例区分同一 Case 的画像和版本变体。 |
| `Profile`、`ProfileComparison` | 匿名画像 ID、风险偏好、投资期限、知识水平或经验。对照组记录同一问题下的回答 ID、画像 ID 和必须保持一致的客观字段。 |
| `Evidence` | `evidenceId`、实体、字段、值、单位、数据所属日期／报告期、更新时间、来源、数据类型、适用的时效配置及示例标记。定性事实如客观风险等级也可作为证据字段。 |
| `HotContext` | `contextId`、新闻标题、来源、发布时间、有效期限、示例标记。 |
| `Version` | 版本 ID、类型（Agent 模型／Prompt／数据集）和显示名称。预置结果需同时记录三类版本，Judge 使用的评测模型和 Agent 模型分别记录。 |
| `EvaluationResult` | `resultId`、Case 与回答引用、三类版本、评测时间、来源（预置或本次运行）、执行状态、Judge 使用情况、各维得分与依据、综合分、通过／警告／失败、高风险标记、问题明细。 |
| `Finding` | 错误类型、严重级别、答案片段或缺失项、匹配的原始证据或规则依据、归因和建议修复方向。每个结果可含多项发现。 |
| `Review`、`Feedback` | 复核关联 `resultId`，包含待复核／确认问题／驳回问题、备注和更新时间。反馈关联 `answerId`，包含有帮助／无帮助与更新时间。 |

## 5. 数据集与质量标准

预置 24 个基准 Case。基准回答覆盖 12 条正常、12 条有问题的样例。为至少 4 组个性化对照和至少 2 组版本回答对照附加回答变体或配对结果，沿用原 Case ID，变体计入各自的对照样本数。

| 意图 | 数量 | 质量判定重点 |
| --- | ---: | --- |
| 行情问答 | 5 | 回答所问标的和时间范围，价格或涨跌幅、单位、来源和数据日期与证据一致。最新行情按适用时效规则核验。 |
| 基金问答 | 5 | 核对净值和净值日期、收益率与收益区间，回答用户所问的风险与表现。 |
| 财务解释 | 4 | 正确解释指标，区分实体、报告期、口径和单位，并在涉及历史数据时核对所问期间。 |
| 个性化问答 | 5 | 允许按画像改变表述、解释深度和提示重点，保持净值、财务数据、客观风险描述等事实一致。 |
| 合规问答 | 5 | 识别确定收益承诺、绝对化措辞、违规买卖指令、个人信息或不必要的 KYC 暴露。 |

问题样例覆盖六类归因，并包含细微差异。用例包括净值数值错、数字正确但已过期、结论正确但缺来源、遗漏所问风险、随画像改变事实、引用已失效热点。样例的来源、行情、新闻、匿名画像和版本评测结果均在界面中标记为模拟数据。核验以样例记录的回答时间为基准，保证演示结果可复现。若补充真实核验案例，明确其来源及数据时间，并将其与模拟样例一起纳入可追溯展示。

## 6. 评测、核验与归因

| 维度 | 权重 | 依据与可计算信号 |
| --- | ---: | --- |
| 回答相关性 `R` | 20% | Judge 根据该意图的判分要点给出 0–100 分，评估是否回答主要问题、是否遗漏关键点、表达是否清楚。 |
| 事实准确性 `F` | 25% | 对照证据核对预期字段，逐项记录数值、单位、实体、报告期或来源的匹配结果。区分事实不符、缺少引用和证据不足。 |
| 时效性 `T` | 15% | 按数据类型判断日期、适用报告期和有效期限。最新行情看数据年龄，历史财务数据看题目要求的报告期，热点看发布时间和有效期。 |
| 个性化一致性 `P` | 15% | 对照同一问题、证据和版本下的不同画像回答，核对预先指定的客观字段。可比较事实发生漂移时标记 Personalization Drift。 |
| 合规与隐私 `C` | 25% | 结合规则命中和 Judge 语义风险，记录命中类型、严重程度和依据。规则需考虑否定、转述、风险教育以及给出建议的语境。 |

各维得分范围为 0–100。五维都有有效分数时，综合分为 `S = 0.20R + 0.25F + 0.15T + 0.15P + 0.25C`。记录各维依据以及适用和可核验状态。无画像对照等情况应明确展示「未执行对照」，证据缺失应明确展示「未核实」。首次实现前需固定各维评分细则、通过／警告／失败阈值，以及有维度不适用时的计分和聚合口径，并将其纳入测试说明。

严重合规违规或隐私泄露一经自动评测判定即标为高风险，自动结论为失败。执行状态与质量判定分别记录。Judge 未配置、超时或返回无效内容时，展示已获得的规则结果和未完成的维度，标明评测未完成。已确认命中的高风险规则仍需显示。预置分数始终标明来源，运行评测时展示当次实际执行结果。

| Bad Case 类型 | 触发情形示例 |
| --- | --- |
| 答非所问 | 偏离目标，或遗漏问题要求的关键内容。 |
| 事实错误 | 数字、单位、客观事实错误，或应引用的来源缺失。在详情里明确区分这些子情形。 |
| 时效过期 | 用过期行情回答最新行情问题，或用已失效热点支持当下判断。 |
| 个性化失真 | 用户画像变化导致客观事实改变。 |
| 合规违规 | 保证收益、绝对化投资表述、违规买卖指令。 |
| 隐私泄露 | 公开用户身份信息，或在回答中不必要地披露 KYC 信息。 |

问题明细展示类型、具体内容、原始证据或规则依据、原因和修复方向。缺少来源、证据或字段时，指出缺项及其核验影响。回答中同一错误同时违反事实证据与画像一致性时，可以保留两个归因。复核状态与反馈独立于自动结果，均保留原自动判定和依据。

当前规则版将逐项结论记录为通过、失败、待核验或不适用。综合分按适用维度的原权重归一化，待核验项计入适用检查分母，执行状态标记为未完成。严重合规或隐私命中始终为高风险失败。接口支持 `answerId` 或 `answerIds`（每次最多 5 条），分开保存 `ruleResult` 与 `judgeResult`。本阶段仍按确定性规则计算五维综合分，Judge 的语义评分与辅助归因独立显示；任一模块判定高风险时，运行结果标记高风险失败。各时效阈值、合分细则和运行时输出字段见 [测试说明](TESTING.md)。

## 7. 页面与操作

### 总览 `/`

- 展示已评测问答数量、平均质量分数、高风险问题数量、待人工复核数量。
- 用简单图表展示五个维度平均分和六类 Bad Case 分布，并展示最近评测记录，支持跳转详情。
- 标明样例来源和统计范围。基准问答优先使用最新实时结果，无实时结果时使用预置结果。高风险按回答计数，待复核按当前有发现或高风险且尚未处理的结果计数。平均值使用有效分数，显示参与统计的样本数。用户反馈统计覆盖基准与变体回答，每条回答计入最新的一票。

### 问答评测中心 `/cases`

- 提供运行评测入口，以及意图、错误类型、评测状态、分数区间和风险等级筛选。每次最多选择 5 条。运行期间按实际返回逐条更新进度，执行异常定位到受影响记录。可切换到含版本及画像变体的范围。
- 表格包含 Case ID、意图、问题、Agent 模型、Prompt、综合评分、评测结果、查看详情入口。未评测和未完成状态有清晰标识。

### 案例详情 `/cases/[id]`

通过案例入口查看正常与异常结果。链接可定位到相应回答或评测结果。

1. **原始问答**展示问题、Agent 回答、回答时间和版本。
2. **用户画像与热点上下文**展示匿名 KYC、新闻标题、来源、发布时间和有效期。有画像对照时展示对照回答和关键客观事实差异。
3. **数据证据**并列显示 Agent 引用值与原始值、单位、来源、数据日期及更新时间，并说明核验结果。
4. **评测结果**显示五维与综合分、执行和风险状态以及 Bad Case 归因。
5. **人工复核与用户反馈**支持确认问题、驳回问题、添加备注，以及有帮助／无帮助。反馈作为体验信号，不参与事实正确性或自动风险判定。

### 版本对比 `/comparison`

- 支持查看模型 A／B、Prompt V1／V2 和数据集版本对比。显示结果来源、配对数量、两侧平均综合分、五维平均分及变化、Bad Case 和高风险案例数量。
- 同一比较维度使用两侧共有的 Case ID 配对，平均分变化取各指标两侧均有有效分数的样本。个性化变体应匹配同一画像或对照组，避免重复计数。
- 模型或 Prompt 对比优先使用只改变所选维度的配对样例。若多个版本项同时变化，仅描述版本组合的差异。数据集版本对比优先复用同一回答，说明证据或评测口径发生了哪些变化。仅单侧存在的案例可披露覆盖情况，从配对统计中排除。
- 版本页分别比较预置结果与实时结果。实时模式只纳入两侧均已运行且 Judge 方法一致的配对：同一 Judge 模型成功输出，或两侧均仅有规则结果。`POST /api/evaluate` 评测已有回答，生成版本回答属于后续能力。

页面视觉参考沿用 AGENTS.md 中每页附的治理、可观测性和调试界面。主导航为总览、问答评测、版本对比，案例详情通过记录进入。

## 8. 需求口径与实现风险

| 事项 | 本规范采用的口径 |
| --- | --- |
| 24 小时与 48 小时 | 24 小时用于交付可运行 MVP，48 小时为完整候选人材料的提交期限。 |
| 筛选列在 P1，评测中心又明确要求筛选 | 三项明确的页面基础筛选纳入 P0，记录文本搜索和进阶筛选留在 P1。 |
| 人工「通过」与「确认问题」用词不同 | 界面采用「确认问题／驳回问题」，明确作用对象为自动发现。通过／警告／失败用于自动结论。 |
| 版本页详细列出模型和 Prompt，P0 另要求数据集版本 | 四页结构下，在版本对比页覆盖三类版本，使用带版本键的可配对预置结果。 |
| 样本总数与配对数量 | 24 条指基准问答。画像和版本对照复用 Case ID，并附回答变体或配对结果。 |
| 真实核验、真实 Judge 和预置结果 | 模拟证据可独立支撑演示，真实 MCP 可选；运行链路要能调用配置好的 Judge。预置评测结果用于演示和对比，有明确来源标识。 |

- **证据匹配。** 按实体、字段和日期定位后再比较，处理百分比、单位倍数和小数精度。保留原值、标准化值与核验依据。字段缺失或来源未知时保持可追溯的未核实状态。
- **时效边界。** 使用明确时区、回答时间和数据类型。最新行情阈值、历史报告期和新闻有效期各自配置，并测试边界值。
- **评分与归因。** 题目给出权重，细则和阈值仍待实现时定稿。用同一套可复现口径生成基准结果并核对页面汇总。区分自动归因、复核结论和用户反馈。
- **Judge 与外部接口。** 校验结构、分数范围和枚举。考虑超时、限流、无效响应以及回答文本中的指令干扰。外发评测输入只取任务所需字段，真实身份信息和密钥不得进入 Judge 输入或样例。
- **版本和状态。** 固定配对样本、版本键和统计分母，避免重复运行造成重复计数。浏览器存储需容错读取，复核与反馈的引用需在刷新和重新评测后仍指向对应记录。

## 9. 验收与提交

- 在可访问的 Web URL 中完成主链路演示。打开总览，按意图、类型和状态筛选，运行评测，查看数值与时效证据、画像对照和风险归因，提交复核与反馈并刷新验证保存，再查看三类版本的配对对比。
- 用典型样例追溯关键分数和结论至 Case、回答、版本、证据及规则命中或 Judge 依据。核对综合分、维度均值、问题计数和版本对比的配对分母。
- 在测试说明中覆盖主链路、正常和错误输入、单位或精度差异、缺证与缺来源、日期边界、相同与漂移的画像对照、严重合规与隐私门槛、Judge 或接口失败、浏览器状态恢复及版本配对。
- 提交可访问且可操作的 Web 产品 URL、GitHub 仓库及 README。README 说明目标用户、核心设计、AI 角色、数据使用、已知边界和未做事项。
- 提交 60–180 秒演示视频、AI 使用与验证记录、测试说明。建议将测试和 AI 使用记录分别保存在 `docs/TESTING.md` 与 `docs/AI_USAGE.md`。

## 10. 当前工程基线
